                                            Abstract

Shop360° is a mobile shopping app that provides Augmented Reality (AR) to make online
shopping better. The application allows customers to view and play with 3D product models in
their real time environment with the phone's camera which allows them to "see" how something
would look in their world before buying it. For example, customers can place furniture in their
rooms with the help of Markerless AR.

The application is built with React Native for cross-platform use, and Expo Go is used in the design
and testing phase. Augmented Reality features are implemented with ViroReact which allows
Markerless AR experiences on Android devices that support ARCore. Product pictures and models
are kept in Firebase Storage whereas user data, products, reviews, chats and wishlists of the users
are kept with Firestore.

The app also includes Firebase Authentication to handle safe user login, sign-up and role-based
access with Custom Claims. This allows normal users and admins to use the same app but with
different access and features. Admins can add or modify products as well as handle user reviews
and manage the app. Vendors can upload or edit the products whereas Users can browse products,
add to a wishlist, write reviews, and preview them in AR.

Secure admin / vendor activities like product management and payment processing are
accomplished through a Firebase backend that communicates with the app through secure APIs.
Simple chat functionality for user-admin communication is also present within the app.

Shop360° aims to reduce the need for massive physical display rooms by helping businesses
showcase their goods online. It is a cost-effective and modern way of helping businesses especially
in Pakistan and connect with a wider audience while delivering an experiential and immersive
shopping experience to its users. This app's tagline says it all: "See It. Try It. Buy It."

Chapter 1: Introduction to the Problem

1.1 Introduction


The e-commerce industry has been rapidly growing over the last few years. It has become easier to
buy products as the e-shopping experience has made it more convenient for customers to reach a
broader market and shop online. But one of the major problems still remains that in online
marketing customers are facing an issue to visualize the products in real time [1][2]. This leads to
confusion and makes the decision of buying trickier. Especially when buying products like
furniture, etc. the major problem is of real-time dimensions of the product and inability to visualize
the product in their own available space. This increases customer dissatisfaction and also results in
higher return rates. If we look into businesses, companies that deal with furniture, sanitaryware,
clothing, etc., spend a lot of money on expensive show-rooms for their products which not only
increases the maintenance costs for them but also makes it more difficult to manage, especially for
small scaled businesses.
Augmented Reality (AR) has been introduced to the market and has a potential solution to resolve
these issues. AR would enable users to visualize virtual objects to the users in their real-time
environment. Shop360° is an AR based mobile application that will enhance the online shopping
experience by allowing its users to interact with the 3D models of products such as furniture [5],
sanitaryware or even clothes, before purchasing. This would help them place the model of the
product in their real-time environment and decide accordingly. By integrating AR into e-commerce,
this project aims to reduce the gap between the physical and digital shopping experience [2].



1.2 Purpose


In e-commerce, customers often struggle with the decision of buying a product online.
Uncertainties due to the inability of interacting with the product and visualization in real-time
environment leads to increase in higher return rates or dissatisfaction. Maintenance of such
expensive showrooms is also one of the major problems faced by companies.

These problems can be solved through this approach of Augmented Reality in e-commerce as users
would be able to view and interact with a 3D model of the product in their real-time environment.
Additionally, customers will not have to visit a physical store for product satisfaction which will
decrease return rates and product dissatisfaction with convenience [6]. Companies or businesses
would also not require an expensive physical showroom as their products can be viewed by the
users through the mobile application which is an innovative alternate to physical showrooms. This
would decrease the operational costs and would be really beneficial in local markets like in Pakistan
where e-commerce is growing and businesses seek cost-effective ways to showcase their products.

1.3 Objective


The main objective of this project is to develop an Augmented Reality based mobile application
which will enhance the online shopping experience by allowing users to visualize products in their
real-time environment before purchasing a product. Following are the major objectives to aim for
in this project: -

   •   Create an Augmented Reality (AR) based Mobile Application for e-commerce dealing
       with products such as furniture, sanitaryware, etc.
   •   Implement product visualization which will enable users to preview and interact products
       such as furniture, sanitaryware, etc. in Augmented Reality.

1.5 Proposed Solution

Shop360° is a mobile application that integrates Augmented Reality (AR) for online shopping

The objective of this Software Requirements Specification (SRS) document is to present with a
detailed description of the functional and non-functional requirements for the implementation of
the Shop360° mobile application. This document is intended to act as a reference for all
stakeholders of the project such as the developers, testers, project managers, and future maintainers.
The main purpose of Shop360° is to offer users an Augmented Reality (AR)-based e-commerce
website where they can see products (clothing, furniture, accessories, etc.) in the real world through
their smartphone cameras prior to purchasing. This SRS will establish how the system will act, how
it works with Firebase and how the system gets interacted by different roles of the users (admin or
customer) and how the products would be rendered in real-time environment through the app.

and the Testers and Project evaluators which would in this case be our respected evaluators assigned
our project to evaluate and any personnel who want to check our product for future upgradation or
scaling as for business purposes or educational purposes.

and real-time way.
Firebase Authentication: A service by Firebase that allows users to sign in using email, password,

3D models.

ViroReact: An open-source AR and VR framework for React Native that enables rendering of 3D
models in real-world environments.
3D Model: A digital representation of an object in three dimensions, used in AR to display products
virtually.
Markerless AR: A type of AR that does not require a printed marker (like a QR code) and instead
uses the environment for placing virtual objects.
Hybrid Architecture: A software structure that combines multiple technologies or systems, like
using Firebase for frontend/backend and for secure admin routes.

5.2.3 Decision Table Testing

Decision Table Testing is a black-box testing technique that uses a table format to represent
different combinations of conditions and their corresponding actions/outcomes. This method
ensures that each possible branch from each decision point is executed at least once, thereby
ensuring that all reachable code is executed.

Format:

    ➢   Y → Yes / True / Condition is met
    ➢   N → No / False / Condition is not met
    ➢   – → Not Applicable
    ➢   X → Action is executed / Outcome occurs

•   User Sign Up Decision Table

    Tests all possible combinations of conditions when a user attempts to sign up with email and
    password.

Conditions:
   o C1: Email format is valid
   o C2: Email is not already registered
   o C3: Password meets minimum length (≥6 characters)
   o C4: Password is strong (Firebase validation)
   o C5: Password and confirm password match
   o C6: Name field is not empty

Actions:
   o A1: Create user account
   o A2: Send verification email
   o A3: Display error: "Invalid email format"
   o A4: Display error: "Email already in use"
   o A5: Display error: "Password must be at least 6 characters"
   o A6: Display error: "Password is too weak"
   o A7: Display error: "Passwords do not match"
   o A8: Display error: "Name is required"

5.3 White Box Test Cases

White box testing is a testing technique, that examines the program structure and derives test data
from the program logic/code. The other names of glass box testing are clear box testing, open box
testing, logic driven testing or path driven testing or structural testing.

5.3.1 Cyclomatic complexity

Analysis Methodology:
    •   Formula: M = E - N + 2P
           o E = Number of edges in the control flow graph
           o N = Number of nodes in the control flow graph
           o P = Number of connected components (typically 1 for a single function)
    •   Decision Points include: if statements, loops, switch cases, try-catch blocks, ternary
        operators, and logical operators (&&, ||)
    •   Complexity Thresholds:
           o 1-10: Low complexity (acceptable, easy to maintain)
           o 11-20: Moderate complexity (should be reviewed, consider refactoring)
           o 21-50: High complexity (should be refactored, difficult to maintain)
           o >50: Very high complexity (must be refactored, high risk of errors)

Testing Requirements: The cyclomatic complexity score indicates the minimum number of test
cases required to achieve complete branch coverage. Each function’s complexity represents the
minimum test cases needed to test all possible execution paths.

5.5 Stress Testing:

Stress Testing focuses on extreme conditions beyond normal capacity, system behavior at breaking
points, recovery after overload, and data integrity under stress.

Key Stress Testing Principles:

   •   Breaking Point Identification: Know when and how the system fails
   •   Degradation: System should degrade gracefully, not catastrophically
   •   Data Integrity: 100% data integrity must be maintained under all stress conditions
   •   Recovery Mechanisms: System must recover successfully after stress
   •   User Experience: User experience should remain acceptable even under stress
   •   Error Handling: Clear, actionable error messages during stress

Network Conditions for Stress Testing

   •   Extreme Slow Network: Simulated very slow connection (50-100 Kbps)
   •   Intermittent Network: Frequent connection drops and reconnections
   •   High Latency: Simulated high latency (500ms+)

   •   Complete Network Failure: No network connection for extended periods
   •   Bandwidth Throttling: Limited bandwidth scenarios

Chapter 7: Summary & Conclusion

7.1 Summary

Shop360 is a revolutionary mobile application that has been conceptualized to fill the gap that
existed between online shopping and offline shopping with the use of Augmented Reality (AR).
This mobile application was created as a final year project and has the capability of allowing
consumers to visualize the product in their environment before purchasing.

The application was developed using React Native and TypeScript. The backend framework is
based on Google Firebase, and it provides a high level of efficiency in managing user
authentication, real-time product information, and storing multimedia contents. With the help of
the @viro-community/react-viro library, high-quality 3D model rendering and AR functionality
are successfully integrated in Shop360 for Android devices.

7.2 Conclusion

Shop360's development and launch mark an important milestone in immersive e-commerce.
Throughout this project, we successfully achieved the main objective of developing a functional,
user-centered mobile application that combines advanced AR capabilities with the usual set of e-
commerce features. The application overcomes the "tangibility gap," often seen as one of the most
significant online shopping drawbacks, and allows users to view furniture, decor, and other
products in their space with scale accuracy.

It has been a very technically dense synergy between cross-platform frameworks and native
modules. The choice of React Native, combined with TypeScript, proved instrumental in scaling
the foundation of this project because its building blocks were developed fast and with maintainable
logic. Introducing Firebase as a backend-as-a-service (BaaS) further validated its utility in handling
real-time data synchronization. This allowed for user interactions, from safe authentication to
instant updates on product catalogs, to take place without managing a custom server infrastructure
overhead. Moreover, the process of testing was accelerated using Expo Go on physical Android
devices to ensure that the AR features were thoroughly checked in real-world scenarios.

However, it should be noted that this project also works under some constraints. As discussed in
the phases of the development of this application, it can only be used on the Android system. This
is because the application was limited, in the first place, by the current structure of the used AR
libraries and the intention of being initially compatible with ARCore. Although this application for
Android provides an optimally seamless user experience, it, in fact, fails to serve a major portion
of the iOS user base. Moreover, despite having an easy shopping flow mechanism using libraries
such as "react-navigation" or "react-native-vector-icons," some advanced functionalities such as

Chapter 9: Lessons Learnt and Future Work

9.1 Lessons Learnt

The realization of the project Shop360 taught us several things about the challenges and
complexities involved in creating an immersive mobile application. The first realization was the
complexity of cross-platform AR development. Although React Native allows for a high degree of
flexibility in UI/UX design, the realization of high-performance AR APIs proved to be a challenge,
for which we understood the importance of understanding Android native compatibility.

Secondly, the importance of Backend-as-a-Service (BaaS) solutions, such as Firebase, could not
be more clear, as the use of Firebase showed how much our development process could benefit
from, basically, delegating authentication and database handling to Firebase, which left us with
ample resources to work with regarding the actual logic, again the AR part.
Finally, we realized the value of user-centric design in 3D spaces. While designing interfaces for
placing digital content over the real world, it's essential to adopt a strategy which is different from
the way 2D applications are usually developed. Learning about scaling 3D models appropriately
and making sure the UI does not cover the camera's perspective was an essential takeaway in the
area of spatial computing.

9.2 Future Work

Although Shop360 successfully delivers on its core objectives, several enhancements have been
identified to help transform it into a complete, scalable business solution:

iOS Support with ViroReact: A key next step is expanding platform compatibility by supporting
iOS devices. This involves enabling ViroReact with ARKit integration to ensure smooth AR
experiences across both Android and iOS.

AI-Driven Product Recommendations: We plan to introduce an AI-powered recommendation
system that analyzes user activity—such as browsing behavior, purchase patterns, and time spent
viewing specific 3D models. This feature will suggest products based on user interests, increasing
personalization and boosting conversion rates.

Enhanced Virtual Try-On: We intend to expand AR capabilities further by incorporating Face
Mesh technology. This advancement will enable users to virtually “wear” accessories such as
glasses or hats in real time, offering a more immersive and interactive try-on experience beyond
simple object placement.

Appendix H: Security Practices

To protect data and secure the app, the following practices were used:

   •   Firebase Authentication was used for user login and registration with Email/Password and
       Google Sign-In providers.
   •   Email verification is required for most authenticated operations to prevent unauthorized
       access.
   •   User roles (admin, user) are stored in Firestore user documents and verified server-side
       through Firestore Security Rules.
   •   Role assignments can be pre-configured in Firestore before user signup for admin access.
   •   Authentication tokens are managed by Firebase SDK and automatically refreshed.
   •   Comprehensive Firestore Security Rules were implemented to enforce data access
       controls:
           o Users can only read/write their own user profile, cart, wishlist, orders, addresses,
               payment methods, and notifications.
           o Email verification is required for all authenticated operations (except public
               product/category reads).
           o Admin users have elevated permissions to manage products, categories, and view
               all user data.
           o Products and categories have public read access but admin-only write access.
           o Role assignments collection allows users to read only their own assignment
               document.
           o Tickets collection allows users to create and read their own tickets, while admins
               can read and update all tickets.
           o Order cancellation requests can only be made by the order owner, and admins can
               approve/reject cancellations.
           o Stock updates are restricted to decrements only (to prevent stock manipulation).

   •   Field validation ensures only allowed fields can be written and data types are enforced.
   •   Timestamp fields (createdAt, updatedAt) are managed server-side using
       serverTimestamp().
   •   Firebase Storage Security Rules were implemented to control file access:
           o Product images and 3D models have public read access (anyone can
               view/download).
           o Write access (upload, update, delete) is restricted to verified admin users only.
           o All other storage paths are denied by default.
   •   Sensitive data like API keys and OAuth client IDs are stored in native configuration files
       (not in JavaScript code).
   •   No authentication tokens or user credentials are stored in AsyncStorage or exposed in
       client-side code.
   •   Payment method data (card numbers) are never stored in full; only last 4 digits, card type,

   •   All API calls to Firebase are made over HTTPS.
   •   Firebase SDK handles certificate pinning and secure connections automatically.

   •   Admin role is assigned through Firestore documents and verified in Security Rules.
   •   Admin operations (product management, user management, order management) are
       protected by Firestore rules.
   •   Regular users cannot escalate their privileges or access admin-only data.

Appendix I: Performance Consideration

To make sure the app runs smoothly and doesn't crash on low-end devices, the following
performance improvements were made:

   •   All 3D models used in AR are optimized binary glTF (.glb) files for faster loading and
       smaller file sizes.
   •   Models are loaded on-demand from Firebase Storage instead of bundling them in the app,
       reducing initial app size.
   •   Model metrics (scale, footprint, local offset) are calculated to ensure appropriate sizing in
       AR scenes.
   •   Model loading progress is tracked and displayed to users.
   •   Failed model loads are cached to prevent repeated failed requests.
   •   Firestore queries use pagination and filters to limit data load and reduce read operations.
   •   Real-time subscriptions are used efficiently with proper cleanup to prevent memory leaks.
   •   Product catalog uses efficient queries with category filters and featured product flags.
   •   Collection group queries are used sparingly and only for admin operations.
   •   Data is cached locally using AsyncStorage for offline access (cart, wishlist, user
       preferences).
   •   React Native lazy loading and code splitting are used where appropriate.
